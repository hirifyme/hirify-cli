# Hirify CLI - Claude Code Instructions

Тонкий индекс проекта. Только вход в контекст; правила обязательны и перекрывают дефолты.

## Продукт

**Hirify CLI - доступ AI-агента к вакансиям Hirify:** фиды пользователя, поиск и «куда
откликнуться». Человек входит браузером (`hirify login`), а не вставляет ключ руками.

Тот же API отдаётся и по MCP (`api.hirify.me/api/mcp`), с тем же аккаунтом. Обе реализации наши,
берут ту, которую поддерживает агент.

**Два канала раздачи, и они не альтернативы:** npm везёт исполняемое (`npx hirify …`), skills.sh -
инструкцию для агента (`SKILL.md`, `npx skills add hirifyme/hirify-cli`). Скилл велит агенту звать
бинарь, поэтому нужны оба.

**Паритет (приказ Admin 18.08):** «наш API access должен позволять делать с сайтом все то же самое,
что делать может человек. Только переложить эту работу на агента». Отсюда `apply`, сохранённые
поиски и вебхуки в CLI, и отсюда же отмена решения 05.08 «эндпоинт отклика не строим» - но только
для вакансий, размещённых у нас. Остальные по-прежнему через `reveal`, откликается человек.

**Главное правило продукта:** чтение бесплатно, а раскрытие вакансии тратит дневной лимит.
Поэтому агент сначала отбирает чтением и только потом раскрывает то, что реально подходит.
Точные лимиты и поведение - в `SKILL.md`, не в этом файле.

## Границы

- **Проект переехал в группу Hirify и получил свой репозиторий** (10.08, слово Admin: CLI и скилл -
  часть бизнес-продукта, а не платформы). До этого он полтора месяца жил одной копией на диске
  станции без истории.
- **Публичный дом - `github.com/hirifyme/hirify-cli`** (орг заведена Admin 17.08, репозиторий заведён
  приватным 17.08). Туда уезжает только продукт: `bin/`, `skills/`, `scripts/`, `README.md`,
  `package.json`, `LICENSE`, `NOTICE`, `.gitignore` - и ровно этот список, восемь путей.
  `NOTICE` появился с переходом на Apache-2.0 (25.08): npm кладёт в тарбол `LICENSE` сам, а
  `NOTICE` - нет, поэтому он ещё и вписан в `files` в `package.json`.
  **Этот файл наружу не едет:** он про внутреннюю кухню и станционные пути. Поэтому
  публичная история начата с нуля одним коммитом, а не перенесена отсюда: в старых коммитах лежит
  этот файл со станционными путями.
- **Как выкатывать наружу:** `origin/main` - это ОДИН коммит с текущим состоянием продукта, а не
  наша история. Собрать чистое дерево из перечисленных путей, сделать orphan-коммит и запушить его
  с `--force`. Здешние `master` и ветки вкладок - рабочая история, наружу она не едет.
  Причина, найденная приёмкой 18.08: пока коммиты уезжали один в один, в публичной истории осели
  русские тексты продукта и комментарий, называющий `CLAUDE.md` по имени. Секретов там не было, но
  публичная история продукта - это его лицо, и начинаться она должна с продукта.
- **Публикация в npm и открытие репозитория - действия наружу и необратимые.** Только по явному
  слову Admin в момент публикации, не «по брифу».
- 🔴 **Два канала открываются В ОДИН ЗАХОД, порознь нельзя.** README читают только те, у кого уже
  есть репозиторий, и он ведёт в npm; help самого CLI есть только у тех, кто уже поставил пакет, и
  он ведёт на GitHub. Ссылки идут по кругу, поэтому открытый раньше канал ровно на этот срок врёт
  каждому, кто в него зашёл. Дисклеймеры в README эту дыру не чинят: чинит только одновременность.
- 🔴 **Всё, что уезжает в пакете, пишется по-английски.** README, вывод CLI, `SKILL.md`, комментарии
  в коде. Слово Admin 18.08: «тексты на английском и никакого жаргона и твоей странной терминологии,
  почитай как нормальные продукты описывают свои cli». Каналы раздачи мировые (npm, skills.sh), и
  русский текст в них выглядит как внутренний файл, случайно выложенный наружу. Этот файл -
  внутренний, он остаётся русским.
- **Никаких наших внутренних метафор в текстах.** «Двери», «поверхности», «контуры» - это язык
  внутренних доков, наружу он не едет. Пишем так, как описывают свой CLI обычные продукты.
- **Текст CLI и скилла видит конечный пользователь.** Перед тем как его писать или править,
  загрузи скилл `product-voice`, а сам канон - `hirify-ecosystem/docs/ecosystem/rules/tone-of-voice-canon.md`.
  Персона та же и по-английски: спокойно, уважительно, коротко, без хайпа и жаргона.
- **Ключи и токены в вывод не светить** - никогда.

## Что осталось до публикации (заморожено Admin 18.08 до следующего дня)

Порядок обязателен, каждый шаг ломается без предыдущего.

1. **Ядро выкатывает ветку с обратной связью.** Не наш шаг, но первый. На проде 18.08 ручки
   `POST /api/agent/feedback` нет (404), а способности `agent:feedback` нет в списке сервера, и он
   молча выбрасывает её из запроса на согласие. Проверено живьём: в выданном токене приехало
   `agent:read agent:reveal offline_access`. Дописать способность в уже выданный OAuth-токен нельзя,
   поэтому **каждый, кто войдёт до этого выката, не сможет отправить обращение, пока не войдёт
   заново**.
2. **Открыть репозиторий публичным** и **`npm publish`** - в один заход, см. правило выше.
   Половину порядка (репозиторий раньше npm) держит `scripts/prepublish-check.mjs`.
3. Сказать кабинету (`hirify-nuxt-frontend`), что каналы открыты: у них команды стоят за константой.

Что уже доказано и переделывать не надо: сквозной логин против прода под `ai@hirify.me` 18.08 -
согласие, токены, файл с правами 600, чтение, `reveal` со списанием и дедупом, тихий обмен
refresh-токена. Приёмка §11 принята на `7397cf5` без находок.
